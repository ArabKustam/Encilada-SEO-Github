# capture — запись реального демо

Запускает приложение, выполняет в настоящем браузере сценарий пользователя и сохраняет видео, лог событий и скриншоты.
Записывается только то, что приложение действительно показывает: подмены сетевых ответов и «дорисовки» в сценариях нет.

## Что нужно

- Браузер семейства Chromium. Порядок поиска: путь из `REPOKIT_BROWSER`, сборка Playwright (`npx playwright install chromium`), установленный Google Chrome или Edge.
- `ffmpeg` в `PATH`.
- Всё, что нужно самому приложению для запуска.

## Команды

| Команда | Что делает |
|---|---|
| `capture scenario draft` | каркас сценария из результатов `scan` → `.repokit/capture/scenario.draft.yaml`. Содержит только найденные страницы; действия нужно дописать |
| `capture scenario validate --scenario f.yaml` | проверка по схеме, список нужных переменных окружения и масок |
| `capture run --scenario f.yaml` | видео, лог событий и скриншоты по меткам → `.repokit/capture/<дата-время>/` |
| `capture shots --scenario f.yaml --sizes desktop,tablet,mobile --themes light,dark` | только скриншоты по меткам в разных размерах и темах |
| `capture screenshot --url http://localhost:8000/` | один скриншот страницы без сценария → `docs/assets/screenshot.png` |
| `capture terminal -- <команда>` | выполняет команду и сохраняет её настоящий вывод картинкой → `docs/assets/terminal.svg` и `terminal-dark.svg` |

`--dry-run` показывает план: браузер не запускается, команда не выполняется.
Код выхода 3 — нужен человек: не задана переменная окружения, не найден браузер или `ffmpeg`, приложение не запущено.

## Скриншот без сценария

```bash
repokit capture screenshot --url http://127.0.0.1:8017/ --start "python -m uvicorn app.main:app --port 8017" --themes light,dark
```

Запускает приложение (если оно ещё не отвечает), открывает страницу, ждёт и снимает. Флаги: `--wait-for <селектор>`,
`--wait <мс>`, `--size desktop|tablet|mobile|1440x900`, `--selector <css>` (только один элемент), `--full-page`,
`--out <файл.png>`, `--demo-data`. Тёмный кадр получает суффикс `-dark`. Поля с паролями размываются, как и при записи.
Когда нужно что-то нажать перед снимком — это уже сценарий: `capture shots`.

## Запись терминала

Для утилит командной строки демо — это настоящий запуск:

```bash
repokit capture terminal -- python wordfreq.py book.txt -n 5
```

Команда выполняется в папке репозитория; её вывод (stdout и stderr в том порядке, в каком их показал бы терминал)
записывается текстом в SVG — светлый и тёмный варианты для `<picture>`. Ничего не дорисовывается и не редактируется:

- цветовые коды убираются, значения секретов из окружения заменяются на `[REDACTED]`;
- вывод длиннее `--max-lines` (по умолчанию 30) обрезается, и на картинке это написано;
- ненулевой код выхода не скрывается: он попадает в предупреждение и в запись о происхождении;
- команда, которая ничего не напечатала или не завершилась за `--timeout` секунд, — ошибка.

В `media.manifest.json` сохраняются сама команда, код выхода и коммит. В ответе `--json` есть поле `text` —
тот же вывод для блока кода. Подходит для команд, которые печатают результат и выходят; интерактивные программы не записываются.

## Сценарий

Схема: [schemas/scenario.schema.json](../schemas/scenario.schema.json). Пример: [examples/web-app/demo.scenario.yaml](../examples/web-app/demo.scenario.yaml).

```yaml
schemaVersion: 1
baseUrl: http://127.0.0.1:8017
start:                      # необязательно; если readyUrl уже отвечает, команда не выполняется
  command: python -m uvicorn app.main:app --port 8017
  readyUrl: /health
viewport: { width: 1280, height: 720, deviceScaleFactor: 2 }   # по умолчанию 1920×1080 @2x
pace: human                 # human — плавный курсор и паузы; fast — без них
demoData: true              # в кадре демонстрационные данные; попадёт в манифест
auth:
  storageState: ${env:DEMO_STORAGE_STATE}   # состояние входа тестового аккаунта
mask: [".api-key"]          # размываются в кадре; input[type=password] — всегда
steps:
  - goto: /
  - type: { selector: "#title", text: "Record the demo" }
  - click: "#add"
  - press: Enter
  - hover: ".card"
  - scroll: { to: "#pricing" }        # или { by: 400 }
  - wait: 0.5                         # секунды, или { for: ".loaded" }
  - mark: home                        # скриншот home.png
```

## Секреты

- Значения берутся из окружения через `${env:ИМЯ}`. Если переменная не задана, запись не начнётся (код 3).
- Введённый текст не сохраняется нигде: в логе событий остаётся только количество символов.
- Хэш сценария в манифесте считается до подстановки переменных.
- Маски применяются до загрузки страницы, поэтому замаскированный элемент не попадает ни в один кадр.
- Для входа используйте отдельный тестовый аккаунт. Файл `storageState` не коммитьте.

## Результат

```
.repokit/capture/20261001-172142/
  video.mp4        H.264, 30 к/с, размер = viewport × deviceScaleFactor
  events.json      клики, ввод, скролл, движения курсора со временем от первого кадра
  shots/home.png   скриншоты по меткам, без потерь
```

Каждый файл получает запись в `.repokit/media.manifest.json`: хэш, сценарий и его хэш, адрес, коммит репозитория
(и признак незакоммиченных изменений), версия браузера, применённые маски, пометка о демо-данных.

## Как устроена запись

Кадры снимаются циклом скриншотов через CDP в разрешении устройства, затем собираются `ffmpeg` в видео с постоянной частотой.
Встроенная запись Playwright и CDP-скринкаст проверялись и были отвергнуты: первая даёт мягкую картинку,
второй игнорирует `deviceScaleFactor` и выдаёт около 13 кадров в секунду против 25–45 у цикла скриншотов.

Системного курсора в кадре нет. Его траектория записывается в лог событий, а рисует курсор `studio`.

## Ограничения

- Только веб-приложения и только Chromium. Запись CLI, мобильных и десктопных приложений запланирована на веху M8.
- Частота съёмки зависит от машины и размера окна: на 2560×1440 это около 28 кадров в секунду.
- Тёмная тема в `shots` включается через `prefers-color-scheme`; если приложение её не поддерживает, кадры совпадут со светлыми.
- Если приложение уже запущено, repokit его не перезапускает и предупреждает, что состояние данных могло быть не чистым.
