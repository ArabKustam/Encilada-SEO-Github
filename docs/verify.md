# verify — проверка с чистого клона

Смотрит на репозиторий глазами того, кто его только что склонировал: создаёт временную копию и проверяет в ней README,
ссылки, медиа, секреты и скрытый текст. Исходный репозиторий не меняется; записывается только отчёт `.repokit/verify.json`.

```bash
node packages/cli/dist/bin.js verify run --repo examples/web-app
```

| Флаг | Значение |
|---|---|
| `--source head` | по умолчанию: чистый клон последнего коммита. Незакоммиченные изменения не проверяются, об этом сообщается |
| `--source worktree` | копия рабочей папки без игнорируемых файлов — так репозиторий будет выглядеть после коммита всех изменений |
| `--online` | проверить внешние ссылки README и адрес работающей версии |
| `--exec` | выполнить команды Quick start из README во временной копии |
| `--url <адрес>` | адрес работающей версии; по умолчанию поле `demoUrl` |

Код выхода 1, если хотя бы одна проверка не пройдена.

## Только быстрый старт

```bash
repokit readme verify-quickstart
```

То же: `repokit verify quickstart`. Выполняет команды из раздела о запуске README во временной копии репозитория и отвечает
на один вопрос: сможет ли новый человек запустить проект по инструкции. `--source head` проверяет чистый клон последнего коммита,
`--source worktree` (по умолчанию) — рабочую папку без игнорируемых файлов. Команды из README выполняются на вашей машине —
запускайте проверку только для репозитория, которому доверяете.

## Что проверяется

| Проверка | Не пройдена, если |
|---|---|
| README есть | файла нет |
| Нет незаполненных мест | остались пометки `<!-- FILL -->` |
| Ссылки и картинки ведут на существующие файлы | README ссылается на файл, которого нет в клоне |
| У изображений есть alt | изображение без alt-текста |
| Внешние ссылки отвечают (`--online`) | ссылка не отвечает или возвращает ошибку |
| Работающая версия отвечает (`--online`) | адрес не возвращает успешный ответ |
| Нет секретов | найден токен известного вида, приватный ключ или случайная строка, присвоенная имени вроде `API_KEY`, `password`, `token` |
| Нет скрытого текста | текст, обращённый к автоматическому проверяющему; невидимые символы; HTML, скрывающий текст от читателя |
| Нет служебных файлов | в репозитории `node_modules`, `__pycache__`, `.env`, `.DS_Store`, `*.log`, `.repokit/` |
| Нет слишком тяжёлых файлов | файл больше 95 МБ (предупреждение — от 25 МБ) |
| Медиа укладывается в бюджет | GIF больше 8 МБ или изображение больше 5 МБ в README |
| Происхождение медиа известно | предупреждение: файл не создан через `capture`/`studio` |
| Утверждения подтверждены кодом | доказательство из `claims.json` не найдено в клоне или код изменился |
| Команды из README выполняются (`--exec`) | команда завершилась с ошибкой |

## Секреты

Найденное значение никогда не выводится: в отчёте только файл, строка, правило и первые четыре символа с длиной.
Заглушки вроде `your_api_key`, ссылки на окружение и повторяющиеся символы не считаются секретами; файлы блокировки зависимостей пропускаются.
Это встроенные правила, а не полноценный сканер: сторонние инструменты вроде gitleaks repokit не вызывает.
Секрет, который уже попал в историю git, проверка последнего коммита не увидит.

## Скрытый текст

Ищется во всех текстовых файлах, кроме тестов:

- фразы, обращённые к автоматическому проверяющему: просьбы не учитывать прежние указания, поставить высший балл, обращения вида «если текст читает языковая модель» — на русском и английском;
- символы нулевой ширины и управляющие направлением текста;
- в документах — HTML со стилями `display:none`, `visibility:hidden`, нулевым размером шрифта, белым или прозрачным цветом.

Это набор шаблонов: он ловит известные приёмы, но не гарантирует, что их нет вовсе.

## Выполнение команд (`--exec`)

Команды берутся из блоков кода в разделах «Быстрый старт», «Запуск», «Установка», Quick start, Usage, Installation и выполняются
по порядку **во временной копии**, не в вашем репозитории.

- Команды Python выполняются в отдельном виртуальном окружении внутри копии, чтобы не трогать ваше.
- Команда установки и тестов должна завершиться успешно. Команда запуска считается рабочей, если завершилась успешно
  или продолжает работать через 8 секунд (сервер); после этого она останавливается.
- После первой ошибки остальные команды пропускаются.
- Команды с `sudo`, `rm -…`, передачей скачанного в оболочку и подобным не выполняются никогда.
- Установка зависимостей обращается к сети — это единственная причина, по которой `--exec` нужно включать явно.

Без `--exec` команды только перечисляются в отчёте.

## Чего verify не делает

- Не проверяет, что приложение работает правильно — только что оно запускается.
- Не открывает страницу в браузере после запуска.
- Не просматривает историю git.
