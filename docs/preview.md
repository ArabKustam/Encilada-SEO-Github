# preview — как README будет выглядеть

Один инструмент для двух зрителей: человек смотрит в браузере и заполняет свои поля, Claude Code получает снимки и измеримые
проблемы. Ничего не отправляется наружу: рендер локальный, стили и mermaid берутся из установленных пакетов.

## Веб-интерфейс

```bash
node packages/cli/dist/bin.js preview serve --repo examples/web-app --open
```

Сервер слушает только `127.0.0.1` (по умолчанию порт 4173; `--port 0` — любой свободный).

- **В центре** — README в рамке, как на странице репозитория: таблицы, сворачиваемые блоки, схемы mermaid, `<picture>`, якоря заголовков.
- **Показать:** черновик по плану или текущий `README.md`.
- **Пресет:** «по типу проекта» (`auto`) или фиксированный шаблон `compact` / `showcase` / `technical`, без записи в файл.
- **Тема:** светлая и тёмная; для `<picture>` выбирается источник нужной темы.
- **Ширина:** десктоп или телефон (390 px).
- **Панель справа:**
  - «Разделы» — чем заполнен каждый раздел и чего не хватает;
  - «Утверждения» — статус и фрагмент кода-доказательства по клику;
  - «Медиа» — вес каждого файла и его происхождение;
  - «Человеку» — решения, которые остаются за вами, предупреждения и ошибки черновика;
  - «Поля» — форма: название, тэглайн, проблема, решение, ссылки, команда, планы, исключённые разделы;
  - «Было/стало» — diff текущего README и черновика.
- **Применить…** показывает diff и записывает `README.md` только после подтверждения; прежняя версия сохраняется в `.repokit/readme.backup.md`.
- Страница обновляется сама при изменении файлов проекта.

Форма сохраняет данные в `.repokit/readme.human.yaml` — тот же файл, из которого берёт поля `readme plan`.

## Для Claude Code

| Команда | Результат |
|---|---|
| `preview shot [--themes light,dark] [--widths 1280,390] [--sections] [--source draft\|current]` | PNG всей страницы для каждой темы и ширины → `.repokit/preview/`; с `--sections` — ещё по снимку на раздел |
| `preview check [--source draft\|current] --json` | измеримые проблемы; код 1 при ошибках |

`preview check` сообщает:

- что попало на первый экран при 1280×800 и 390×844: заголовки, число изображений, высота страницы;
- изображения, которые не загрузились, и изображения без alt;
- таблицы, блоки кода и картинки шире колонки;
- схемы mermaid, которые не отрисовались;
- незаполненные места и битые ссылки черновика;
- медиа с неизвестным происхождением и утверждения, не прошедшие проверку;
- отсутствие изображений на первом экране.

Нужен Google Chrome или Edge (либо путь в `REPOKIT_BROWSER`).

## Насколько это похоже на GitHub

Рендер локальный: `markdown-it`, очистка HTML по тем же правилам (вырезаются `style`, скрипты, обработчики событий,
`javascript:`-ссылки) и открытые стили `github-markdown-css`. Это очень близко, но не пиксель в пиксель:

- эмодзи-коды вида `:rocket:`, сноски и списки задач не обрабатываются;
- подсветки синтаксиса в блоках кода нет;
- ссылки на файлы репозитория открывают сам файл, без перехода к строке.

Бейджи shields.io загружает браузер, как и на GitHub; сервер repokit во внешнюю сеть не обращается.

## Безопасность

- Сервер принимает соединения только с этого компьютера и отклоняет запросы с чужим именем хоста.
- Изменять файлы (сохранение полей, «Применить») может только страница, выданная этим сервером: у неё одноразовый токен.
- Отдаются только файлы проекта: ничего из `.repokit/`, игнорируемых путей и за пределами репозитория.
