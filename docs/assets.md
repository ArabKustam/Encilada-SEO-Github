# assets — медиафайлы документации

Следит за картинками и видео, на которые ссылаются README и документы: находит битые ссылки, тяжёлые и забытые файлы,
приводит имена в порядок. Содержимое изображений не меняет — только размер, формат и имя.

## Команды

| Команда | Что делает |
|---|---|
| `assets check` | битые ссылки, тяжёлые и неиспользуемые файлы, неаккуратные имена; код 1 при битых ссылках |
| `assets optimize [--max-width 1600]` | уменьшает слишком широкие и тяжёлые PNG, JPEG, WebP и GIF |
| `assets prune` | убирает из репозитория медиа, на которое никто не ссылается |
| `assets normalize` | переименовывает файлы в `kebab-case` и обновляет ссылки в документах |
| `assets convert <файл> --to png\|jpg\|webp\|gif\|mp4\|webm` | создаёт рядом файл в другом формате |

Все команды, кроме `check`, меняют файлы репозитория, поэтому сначала запускайте их с `--dry-run`.
`optimize` и `convert` требуют `ffmpeg`.

## Где лежит медиа

Рабочие файлы (записи, кадры, черновики) остаются в `.repokit/` и в репозиторий не попадают.
Готовое медиа лежит в одной папке. repokit распознаёт `docs/assets`, `docs/media`, `docs/images`, `docs/img`, `docs/screenshots`,
`.github/assets`, `.github/images`, `assets`, `media`, `images`, `screenshots` и использует ту, где файлов уже больше всего;
если такой папки ещё нет, предлагает `docs/assets`. Относительные ссылки из README работают на GitHub для любой из них.

Ссылки ищутся во всех файлах `.md` и `.html` репозитория и разрешаются относительно документа, в котором стоят.

## Что считается проблемой

| Проверка | Порог |
|---|---|
| Тяжёлое изображение | больше 1 МБ |
| Тяжёлый GIF | больше 8 МБ |
| Слишком широкое изображение | шире 1600 пикселей: GitHub всё равно покажет его в колонке около 900 |
| Неаккуратное имя | пробелы, заглавные буквы, знаки кроме дефиса: `Screen Shot 1.PNG` → `screen-shot-1.png` |
| Неиспользуемый файл | лежит в папке медиа, и ни один документ на него не ссылается |

## Ничего не теряется

- `optimize` сохраняет оригинал в `.repokit/assets-backup/` и заменяет файл, только если он стал меньше хотя бы на 5 %.
- `prune` не удаляет, а переносит файлы в `.repokit/assets-pruned/`.
- `normalize` пропускает файл, если новое имя уже занято.
- `convert` оставляет исходный файл на месте.
- Если у файла была запись о происхождении в `.repokit/media.manifest.json`, новая версия получает запись со ссылкой
  на хеш прежней (`derivedFrom`): видно, что это тот же кадр, только сжатый или переименованный.
