# repokit run — все шаги по порядку

Проводит репозиторий через все готовые сервисы и останавливается там, где нужно решение человека.

```bash
node packages/cli/dist/bin.js run examples/web-app
```

## Шаги

| Шаг | Что делает | Когда останавливается |
|---|---|---|
| `scan` | создаёт `.repokit/`, собирает факты, выжимку и утверждения README | — |
| `brief` | проверяет `brief.json` | правил нет: нужен `--rules <файл>` или `--default-brief`; после `--rules` — пока критерии не размечены по тексту правил |
| `claims` | фиксирует и проверяет доказательства | пока хотя бы одно утверждение не подтверждено строками кода |
| `demo` | записывает демо, монтирует `docs/media/hero.gif` и 3D-версию `docs/media/hero-3d.gif` | нет сценария; сценарий не одобрен (`--approve demo`) |
| `readme` | собирает черновик и записывает `README.md` | запись не одобрена (`--approve readme`) |
| `verify` | проверяет рабочую папку так, как она будет выглядеть после коммита | — (код 1, если проверка не пройдена) |

Код выхода: `0` — всё выполнено, `3` — ждёт человека, `1` — проверка не пройдена, `2` — ошибка использования.

Каждый запуск продолжает с того места, где остановился: выполненные шаги запоминаются в `.repokit/state.json`.
`verify` повторяется при каждом запуске. `--reset` начинает заново.

## Флаги

| Флаг | Значение |
|---|---|
| `--approve demo`, `--approve readme` | одобрить шаг, который ждёт решения |
| `--skip <шаг>` | пропустить шаг; это отразится в списке «для человека» |
| `--rules <файл>`, `--default-brief` | правила хакатона или типовой набор критериев |
| `--scenario <файл>` | сценарий демо; по умолчанию `demo.scenario.yaml` в репозитории |
| `--preset <имя>`, `--preset-3d <имя>` | пресет README (по умолчанию `showcase`) и 3D-пресет (`browser-tilt`) |
| `--exec`, `--online` | передаются в `verify` |
| `--reset` | забыть выполненные шаги |

## Что остаётся человеку

Итоговый список пишется в `.repokit/human-todo.md` и возвращается в `humanTodo`. Туда попадают: что нужно одобрить,
незаполненные разделы README, неподтверждённые утверждения, пропущенные шаги, пометка о типовых критериях,
напоминание о 3D-версии демо (она создаётся, но в README не вставляется), непройденные проверки.

`run` не коммитит, не пушит и не деплоит. Разметку `claims.json` и `brief.json` делает Claude Code или человек —
`run` только ждёт её и проверяет.

## Пока не входят
