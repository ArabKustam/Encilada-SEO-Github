# Плагин для Claude Code

repokit ставится в Claude Code один раз как плагин и после этого доступен в любом проекте на этой машине:
не нужно клонировать репозиторий рядом с каждым проектом, собирать его и объяснять Claude, где что лежит.

## Из чего состоит

| Часть | Что делает | Где лежит |
|---|---|---|
| **Плагин** | упаковка: то, что Claude Code скачивает и подключает | [plugin/](../plugin) |
| **Skill** `readme` | объясняет Claude, когда и как пользоваться repokit: порядок работы, правила честности, когда спрашивать человека | [plugin/skills/readme/](../plugin/skills/readme) |
| **MCP-сервер** | семь структурированных инструментов; каждый запускает команду repokit с `--json` и возвращает её результат | [plugin/mcp/server.mjs](../plugin/mcp/server.mjs), исходник — [packages/mcp/](../packages/mcp) |
| **CLI** | делает всю работу: анализ, план и сборка README, проверки, медиа | [plugin/bin/repokit](../plugin/bin/repokit) → `plugin/lib/repokit.mjs`, исходники — [packages/](../packages) |

Skill говорит Claude, что делать. MCP даёт структурированные инструменты. CLI выполняет работу. Плагин всё это упаковывает.
Логика живёт только в CLI: в skill нет скриптов, MCP-сервер ничего не анализирует сам.

## Установка

В сессии Claude Code:

```text
/plugin marketplace add ArabKustam/Encilada-SEO-Github
```

```text
/plugin install repokit@encilada
```

В открывшейся панели выберите **Install for you (user scope)**. То же из терминала:

```bash
claude plugin marketplace add ArabKustam/Encilada-SEO-Github
```

```bash
claude plugin install repokit@encilada
```

Нужен Node.js 20 или новее. Больше ничего: анализ репозитория, план, сборка и аудит README, проверки и работа с медиафайлами
идут из одного файла внутри плагина.

### Области установки

| Область | Кому доступен плагин | Где записано |
|---|---|---|
| `user` (по умолчанию, рекомендуется) | вам, во всех проектах на этой машине | `~/.claude/settings.json` |
| `project` | всем, кто работает с этим репозиторием | `.claude/settings.json` в репозитории (коммитится); каждый участник один раз выполняет `claude plugin install repokit@encilada --scope project` |
| `local` | вам, только в этом репозитории | `.claude/settings.local.json` |

Терминал, локальные сессии десктопного приложения и расширение VS Code читают одни и те же файлы настроек, так что плагин,
поставленный в области `user`, виден во всех трёх.

**Где плагин не работает.** Облачные сессии Claude Code (в том числе claude.ai/code) не загружают плагины, установленные
на вашей машине. В чате claude.ai и в Cowork плагины с папкой `bin/` не устанавливаются вовсе. Плагин рассчитан на локальный Claude Code.

### Медиа-сервисы — отдельным шагом

Запись демо, скриншоты, монтаж, 3D-сцены и веб-предпросмотр (`capture`, `studio`, `preview`) требуют браузерный движок и
рендерер — около 1 ГБ зависимостей. В плагин они не входят. Когда понадобятся:

```bash
repokit setup
```

Команда клонирует репозиторий repokit той же версии в `~/.repokit/runtime/<версия>`, ставит зависимости и собирает его
(нужны `git`, сеть и `pnpm` — если его нет, используется `corepack` или `npx`). После этого те же команды `repokit capture …`
работают как обычно. До установки они отвечают кодом 3 и подсказкой. `repokit setup --dry-run` показывает, что будет сделано.
Внешние программы — Chrome или Edge, `ffmpeg` — проверяет `repokit doctor`.

## Использование

```bash
cd my-project
claude
```

Дальше обычным языком:

```text
Сделай этому проекту красивый README через repokit.
```

Claude сам выберет skill по описанию. Явный вызов: `/repokit:readme`, можно с уточнением — `/repokit:readme только проверь первый экран`.

Что произойдёт: Claude проанализирует репозиторий, прочитает существующий README, составит план, при необходимости предложит
скриншоты или запись терминала, покажет diff и запишет README только после вашего согласия. В конце — список изменённых файлов
и решений, которые остались за вами.

### Инструменты MCP

| Инструмент | Что делает | Меняет файлы |
|---|---|---|
| `analyze_repository` | тип проекта с фактами, стек, команды запуска, роуты, заглушки, найденные примеры, рекомендуемая структура README | нет |
| `plan_readme` | план и черновик README с состоянием каждого раздела | только `.repokit/` |
| `audit_readme` | непройденные проверки README или черновика | нет |
| `generate_presentation` | diff будущего README; с `apply: true` — запись | `README.md` только с `apply: true` |
| `capture_demo` | запись вывода команды в SVG или скриншот страницы | `docs/assets/`; выполняет команду проекта |
| `verify_repository` | итоговая проверка: пустые места, битые ссылки, alt-тексты, секреты, медиафайлы | нет |
| `run_repokit` | любая другая команда repokit по списку аргументов | зависит от команды |

Путь к репозиторию передавать не нужно: сервер берёт проект, в котором открыт Claude Code (`CLAUDE_PROJECT_DIR`, затем
корни сессии, затем рабочую папку). Другой репозиторий задаётся полем `repo`.

Ограничения сервера, которые нельзя обойти аргументами:

- оболочка не используется — команда запускается списком аргументов;
- `deploy run` и `release create` через MCP не выполняются: публикацию запускает человек в терминале;
- флаг `--confirm` не принимается;
- защита CLI остаётся в силе: содержательный README автора не заменяется без `regenerate: true`, а код выхода 3 возвращается как есть.

Проверить подключение в сессии: `/mcp` — сервер `repokit` должен быть в состоянии connected.

## Разработка

```bash
pnpm install
```

```bash
pnpm build:plugin
```

`build:plugin` компилирует пакеты и собирает `plugin/`: `lib/repokit.mjs` и `mcp/server.mjs` (esbuild), копии схем и шаблонов
README в `resources/`, справочник команд для skill (берётся из `repokit --help`) и версию в манифесте.
Собранные файлы коммитятся: Claude Code при установке копирует папку `plugin/` как есть и ничего не собирает.

Проверка манифестов средствами самого Claude Code:

```bash
claude plugin validate ./plugin
```

```bash
claude plugin validate .
```

Запуск Claude Code с плагином из рабочей папки, без установки (в любом другом проекте):

```bash
claude --plugin-dir /path/to/Encilada-SEO-Github/plugin
```

После правок в `plugin/` в открытой сессии: `/reload-plugins`. В рабочей копии медиа-сервисы уже собраны, поэтому вместо
`repokit setup` достаточно указать на неё: `REPOKIT_RUNTIME=/path/to/Encilada-SEO-Github`.

Тесты плагина — [tests/e2e/plugin.test.ts](../tests/e2e/plugin.test.ts): плагин копируется в отдельную папку с пробелом в пути,
запускается оттуда, MCP-сервер проверяется по протоколу (initialize, tools/list, вызовы, ошибки).
`pnpm check:plugin` падает, если `plugin/` не соответствует исходникам.

### Версия

Одна на всё: поле `version` в корневом `package.json`. С ней обязана совпадать `VERSION` в `packages/core/src/envelope.ts`
(её печатает `repokit --version`, её же сообщает MCP-сервер); `build:plugin` переносит её в `plugin.json` и отказывается
собирать при расхождении. Claude Code считает плагин обновлённым, когда меняется эта версия, поэтому каждое изменение,
которое должно дойти до пользователей, сопровождается её повышением. `repokit setup` ищет в репозитории метку `v<версия>`.

## Обновление и удаление

```bash
claude plugin marketplace update encilada
```

```bash
claude plugin update repokit@encilada
```

```bash
claude plugin uninstall repokit@encilada
```

Автообновление для сторонних каталогов по умолчанию выключено; включается в `/plugin` → Marketplaces.
Медиа-сервисы прежней версии остаются в `~/.repokit/runtime/` — папку старой версии можно удалить вручную.

## Если что-то не работает

| Что видно | Что делать |
|---|---|
| `repokit: command not found` в сессии | `/reload-plugins`; проверьте, что плагин включён: `/plugin` → Installed |
| `/repokit:readme` нет в списке команд | `claude plugin list` — статус должен быть enabled; ошибки загрузки — `/plugin` → Errors |
| сервера `repokit` нет в `/mcp` | в PATH должен быть `node` версии 20+; `claude --debug` покажет, почему сервер не запустился |
| команда `capture` / `studio` / `preview` отвечает кодом 3 | `repokit setup` |
| `repokit setup` не завершился | проверьте сеть и `git`; повтор с нуля — `repokit setup --force` |
| на Windows вне Git Bash нет команды `repokit` | внутри Claude Code она есть всегда; в своём терминале используйте `plugin/bin/repokit.cmd` |

## Безопасность

- Плагин не содержит хуков: ничего не запускается само при сообщениях или правках файлов.
- Сеть используется только по явной команде: `repokit setup`, `verify --online`, `deploy`.
- Команды проекта выполняются только в `capture`, `verify --exec` и `readme verify-quickstart` — skill требует согласовать их с человеком.
- Деплой, релиз, `git push`, удаление и переименование файлов — только после явного подтверждения; через MCP публикация недоступна.
- Значения секретов из окружения маскируются в любом выводе repokit.
